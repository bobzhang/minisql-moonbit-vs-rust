MoonBit vs Rust: a tie decided by how long the agent kept polishing

An AI agent built the same SQLite-compatible database engine nine milestones deep, three times in Rust and three times in MoonBit. Across about 13,000 lines per run, the two languages cost within a few percent of each other. Run-to-run variation was larger than the language difference.

Ratios are MoonBit ÷ Rust, means over 3 complete trials. Below 1.0 means MoonBit used less. Cost is Claude Code's estimate at API list prices; the runs used a subscription.

Where the input tokens went

Most tokens were spent after the tests were green

Every session re-reads its whole context on each call, so input tokens dominate. Splitting each trial at the moment its visible tests first all passed shows that 47–82% of input came afterwards, as agents fuzzed against SQLite, profiled, and chased edge cases on their own initiative. Measured only up to first green, MoonBit used 9% more input than Rust. Its larger primer, re-read on every call, accounts for about 2.1M tokens per trial, which covers essentially all of that gap.

By milestone

MoonBit wrote a little less at almost every step

Output tokens (code plus reasoning) per milestone, MoonBit ÷ Rust, averaged over the three trials. MoonBit came in under Rust on eight of nine milestones, typically by 5–15%. Its compiler errors were more frequent at nearly every milestone and did not taper off, but each one cost only a quick fix.

Findings

What the data supports

  • Agent cost is a draw. Mean estimated cost was $43.86 for Rust and $41.09 for MoonBit (0.94×), with standard deviations of $13.25 and $3.97. The gap is smaller than the noise.
  • MoonBit produces slightly less. 12% fewer output tokens and 12% fewer source tokens in the finished engine, with no borrows, Box, ? or cross-module pub to write. Line counts were about equal.
  • Unfamiliarity shows up as compile errors, not cost. MoonBit's failed-build rate was 13% against Rust's 6%, and it stayed higher at nearly every milestone rather than declining. The 11.7k-token primer kept API lookups to 1.7% of tool calls.
  • The primer is MoonBit's main overhead. Re-reading it on every call cost 4.9M input tokens per trial against 1.1M for Rust's primer.
  • Quality is nearly equal. Hidden-test pass rates were 96.3% for Rust and 95.6% for MoonBit: Rust passed about two more of 242 held-out tests per trial.
  • Stopping behavior is the biggest variable. When to stop polishing decided the cost ranking of individual trials more than the language did.

Method

How the experiment was run

The task

  • minisql: a CLI that runs SQL scripts, compatible with SQLite 3.53
  • Nine milestones, from the core pipeline to reading and writing real SQLite database files
  • 489 conformance tests generated by real SQLite; half visible, half hidden
  • One fresh headless Claude Code session per milestone, same workspace

Fairness controls

  • Identical spec, tests, prompts, model and effort; standard library only, no FFI
  • Identical five-function I/O module in both starter projects
  • Language primers with the same four sections, snippets compiled against the installed toolchains
  • No user settings, memory, skills, MCP servers or web access
  • Rust and MoonBit trials run in parallel pairs

Limits

  • Three trials per language; one model; one kind of program
  • The project suits garbage-collected languages; it never tests concurrency or memory control
  • Output tokens can't be split at first green from the transcripts
  • Engines came out near 13k lines, below the 20k target

Audit: all 54 milestone snapshots passed the rule checks; no session touched the hidden tests or the network; no follow-up prompts or usage-limit interruptions occurred.
